# Контракт между ML/разметкой и интерфейсом

Документ фиксирует **границу ответственности**: что команда разметки/ML отдаёт наружу,
и в каком виде интерфейс координатора это потребляет.

```
┌───────────────────────┐     контракт (JSON / REST)     ┌──────────────────────┐
│  Разметка + ML/движок │  ───────────────────────────►  │  Интерфейс (наш)     │
│  протокол → находки   │   findings + routes            │  рабочее место       │
└───────────────────────┘                                └──────────────────────┘
        ответственность ML                                  ответственность UI
```

Интерфейс **не знает**, как находка найдена (LLM, правила, разметка вручную) — ему важен
только формат результата. Поэтому договориться нужно **один раз**, до конца разметки.

---

## 1. Схема одной записи

```json
{
  "protocol_id": "протоколы Ж ОМТ/1 Ж ОМТ (21).docx",
  "patient": { "id": "П-5840", "age": 53, "sex": "Ж" },
  "study": { "type": "УЗИ органов малого таза", "date": "2026-08-13T10:00:00" },
  "findings": [
    {
      "id": "endometrial_polyp",
      "title": "Полип эндометрия",
      "domain": "Гинекология",
      "status": "trigger",
      "severity": "planned",
      "confidence": 0.9,
      "evidence": "…фрагмент протокола с находкой…",
      "match": "полип эндометрия",
      "attributes": { "size": "12х11мм" },
      "rule_version": "0.1"
    }
  ],
  "routes": [
    {
      "finding_id": "endometrial_polyp",
      "specialist": "Оперирующий гинеколог",
      "next_step": "Консультация оперирующего гинеколога",
      "planned_step": "Гистероскопия / гистерорезектоскопия",
      "target_days": 7,
      "priority": "planned",
      "priority_reason": "Хирургически значимая находка, плановая операция",
      "department": "Координатор хирургического маршрута",
      "urgent": false
    }
  ]
}
```

Правила:
- `patient` — **только обезличенный id**, без ФИО/телефона/СНИЛС.
- Даты — ISO 8601 (`2026-08-13T10:00:00`).
- `attributes` — свободный объект (размер, BI-RADS, TI-RADS…).
- `routes` — **список**: по одному маршруту на каждую находку со `status=trigger`.
  Именно `routes[]`, а не первый элемент: иначе при нескольких находках маршруты теряются.
- `protocol_id` стабилен при повторной выдаче/исправлении протокола.

---

## 1.1. Статус находки — три значения

| `status` | Что значит | Маршрут |
|---|---|---|
| `trigger` | находка подтверждена | **создаётся** |
| `uncertain` | реально противоречивая формулировка | **не создаётся автоматически** → очередь «Требует уточнения» |
| `negated` | находка отрицается | не создаётся |

`evidence` — обязательная цитата из текста для любого статуса (объяснимость — критерий оценки).
Для `uncertain` дополнительно указывается `marker` — какая именно формулировка вызвала сомнение.

### Неопределённость: список синонимов

Врачи пишут по-разному, поэтому маркеры неопределённости вынесены в настройку
`rules/uncertainty.json` (список ведёт медэксперт, правки — без изменения кода):

- **strong (используются):** `нельзя исключить`, `не исключено`, `не исключается`, `под вопросом`,
  `под сомнением`, `сомнительн`, `заподозрить`, `подозрение на`, `дифференцировать`,
  `диффдиагноз`, `требует уточнения`, `требует дообследования`, `неясн`, `неоднозначн` и др.
- **weak (по умолчанию выключены):** `вероятно`, `возможно`, `предположительно`, `может соответствовать`.
  Их включают осознанно: слова вроде «вероятно» часто относятся к причине или локализации,
  а не к наличию находки, и дают ложные срабатывания.

Важно: проверка неопределённости идёт **раньше** отрицания, потому что «не исключено» содержит «не».

Если `status` не пришёл — интерфейс считает находку подтверждённой (безопасный дефолт для демо;
в реальной эксплуатации указывать статус обязательно).

---

## 1.2. Срочность (`priority`) — обязательное поле

Срочность задаётся **детерминированной матрицей правил** (`rules/routing.json`), которая
версионируется и утверждается медэкспертом. **LLM срочность не выставляет** — она может
участвовать только в извлечении фактов из текста.

| `priority` | В интерфейсе | SLA (`target_days`) | Когда ставится |
|---|---|---|---|
| `emergency` | Экстренно | ≤ 1 суток | Угроза жизни/конечности (тромбоз, обструкция) |
| `urgent` | Срочно | ≤ 3 суток | Подозрение на онкологию (BI-RADS 4–5) |
| `planned` | Планово | ≤ 14 суток | Хирургически значимая находка |
| `watch` | Наблюдение | ≤ 30 суток | Динамическое наблюдение |

`priority_reason` — короткое обоснование (1 фраза), показывается координатору.
Если `priority` не пришёл — интерфейс берёт безопасный дефолт `planned`.

## 2. Два способа подключения

### Вариант A — файл разметки (рекомендуется на хакатоне)
ML-команда складывает результат в `data/labeled_routes.jsonl`. Интерфейс подхватит его при старте.

```
sm_case/
└─ data/
   ├─ labeled_routes.jsonl   ← файл от команды ML (если есть — используется он)
   └─ analysis.jsonl         ← иначе берётся результат встроенного движка
```

### Вариант B — REST API (для пилота)
| Метод | Путь | Зачем |
|---|---|---|
| `POST` | `/api/analyze` | Прислать протокол → получить `findings` + `routes` |
| `GET`  | `/api/routes` | Список маршрутов для координатора |
| `GET`  | `/api/routes/{id}` | Детали маршрута |
| `POST` | `/api/routes/{id}/action` | Действие координатора |
| `GET`  | `/api/reviews` | Очередь «Требует уточнения» |
| `POST` | `/api/reviews/{id}/resolve` | Подтвердить/отклонить находку |
| `GET`  | `/api/dashboard` | Показатели воронки |

## 3. Чек-лист: что согласовать с командой ML

- [ ] Идентификатор пациента — обезличенный (`П-XXXX`), не ФИО.
- [ ] Единый справочник `id` находок и их `title` (без расхождений в написании).
- [ ] Значения `severity`: `urgent` / `planned` / `watch`.
- [ ] Кто и по какому правилу ставит `status` (`trigger` / `uncertain` / `negated`).
- [ ] Пополнение списка синонимов неопределённости вместе с медэкспертом.
- [ ] **`priority` для каждой находки** — детерминированные правила, не LLM.
- [ ] Для каждой находки — `specialist` и `next_step` (матрица маршрутизации).
- [ ] Что приходит по протоколу без находок: запись отсутствует **или** пустой `findings`.
- [ ] Формат события при исправлении/аннулировании протокола.

---

## 4. Безопасность данных

- Интерфейс и API разворачиваются **в контуре клиники** (локально), наружу данные не уходят.
- В демо допускается облако **только на обезличенных данных**; в плане пилота —
  локальная модель + локальный OCR.
- Интерфейс хранит минимум: обезличенный id, текст заключения, находки. Без ПДн.

---

## 5. Что делать, пока разметка не готова

Ничего не ждать: интерфейс работает на данных встроенного движка (тот же формат).
Когда команда отдаст `labeled_routes.jsonl` — перезапустить сервер, формат ответов не изменится.
