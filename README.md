# СМ-Клиника · «Не потерять пациента»

Интеллектуальная система выявления клинически значимых находок в протоколах
диагностических исследований и автоматической маршрутизации пациента.

Прототип: рабочее место координатора + автоматические уведомления пациенту (без диагноза).

---

## 1. Проблема

После диагностического исследования пациент получает заключение, в котором может быть
клинически значимая находка. Дальше всё зависит от того, понял ли пациент результат,
вернулся ли к врачу, смог ли быстро записаться, передана ли информация между подразделениями.
Значимая информация часто остаётся в свободном тексте протокола **без автоматического
запуска следующего действия** — и пациент «теряется» между этапами.

**Цель решения:** превратить значимую находку в контролируемый медицинский маршрут.
Система **не ставит диагноз и не назначает лечение** — она распознаёт триггер и организует
следующий безопасный шаг.

---

## 2. Гипотезы

Каждая гипотеза сформулирована проверяемо — с указанием, как мы её подтверждаем.

### H1. Полнота распознавания достижима без обучения модели «с нуля»
Свободный текст протоколов можно разбирать надёжно, если объединить словари синонимов,
основы слов (падежи), контекст органа, числовые условия (BI-RADS/TI-RADS), обработку
отрицаний и неопределённости. На 50–60 протоколах обучение с нуля невозможно — гибридный
подход эффективнее.
**Проверка:** полнота (Recall) и точность на размеченном наборе. *Достигнуто: Recall 100%, Precision 98.8%, F1 99.4%.*

### H2. Разделение «факты» и «решение» даёт управляемость
Если отделить **извлечение фактов** (что написано, с цитатой) от **решения о маршруте**
(детерминированная матрица правил), получаем объяснимость, версионируемость и масштабируемость:
новый триггер добавляется настройкой, а не переписыванием кода.
**Проверка:** добавить новый тип исследования/находку без изменения кода ядра.

### H3. Нейтральное уведомление без диагноза достаточно и безопасно
Пациенту не нужен диагноз — достаточно нейтральной рекомендации и кнопки записи.
Это снижает риск самолечения, стресса и утечки медицинской информации.
**Проверка:** доля записавшихся после уведомления; отсутствие медицинских данных в тексте push (проверяется тестом).

### H4. Автоматическая маршрутизация сокращает разрыв «диагностика → лечение»
Уведомление сразу ведёт на подходящие слоты профильного специалиста, а не заставляет
пациента искать врача самостоятельно.
**Проверка:** доля пациентов, дошедших от находки до профильного приёма (воронка конверсии).

### H5. Спорные формулировки нельзя автоматизировать
«Нельзя исключить», «под вопросом» — это не находка и не отрицание. Такие случаи должны
попадать в очередь **human-in-the-loop**, а не создавать маршрут автоматически.
**Проверка:** доля спорных находок, ушедших в очередь «Требует уточнения», и точность после решения врача.

### H6. Экономический эффект — прирост конверсии, а не перераспределение
Система увеличивает число пациентов, дошедших до профильного приёма/лечения, и снижает
стоимость ручного контроля и повторных коммуникаций.
**Проверка:** расчёт на 1000 исследований (прирост, а не перестановка долей).

### Слои и ответственность

| Слой | Файлы | Отвечает за |
|---|---|---|
| Приём документа | `web/app.py` | docx/txt → текст, валидация |
| **Ядро (извлечение)** | `app/processor.py` | находки, статусы, цитаты, атрибуты, уверенность |
| Правила распознавания | `rules/triggers.json` | словари/синонимы/контекст/условия |
| Неопределённость | `rules/uncertainty.json` | маркеры сомнения, исключения отрицаний |
| Маршрутизация | `rules/routing.json` | специалист, шаг, SLA, приоритет |
| Хранилище и логика | `web/store.py` | маршруты, статусы, очередь уточнения, модельное время |
| Интерфейс | `frontend/` | рабочее место координатора, дашборд |
| Контроль качества | `scripts/` | метрики, аудит, валидация, версионирование |

### Контракт данных (стык с ML/МИС)

Одна запись = один протокол: `findings[]` + `routes[]`.

- `findings[].status`: `trigger` (создаёт маршрут) · `uncertain` (в очередь уточнения) · `negated` (маршрута нет);
- `findings[].evidence`: **обязательная** цитата-доказательство (объяснимость);
- `findings[].attributes`: размер, BI-RADS, TI-RADS и т.п.;
- `routes[]`: по одному маршруту на каждую находку `trigger` (несколько находок не теряются);
- `priority`: `emergency` / `urgent` / `planned` / `watch` — задаётся **правилами**, не LLM.

Полное описание: `docs/api_contract.md`, схема: `schemas/labeled_record.schema.json`.

### Безопасность и развёртывание

- Всё работает **в контуре клиники**: сервер слушает `127.0.0.1`, внешних запросов нет.
- Данные **обезличены**, хранится минимум (id, текст заключения, находки) — без ПДн.
- В уведомлении пациенту **нет диагноза** — только нейтральная рекомендация и запись.
- **Версионирование правил**: `scripts/integrity.py freeze/check` фиксирует версию и контрольную
  сумму; версия видна в интерфейсе. Это обеспечивает воспроизводимость решения.

## 4. Ключевые функции решений

1. **Гибридное извлечение находок из свободного текста**
   словари синонимов + основы слов (падежи: «узл**ы**», «миом**ы**», «кист**ы**») + привязка к органу
   + числовые условия (срабатывают только BI-RADS/TI-RADS 3–5).

2. **Обработка отрицаний с исключениями**
   «конкременты **не выявлены**» → не триггер; но «миома **без признаков роста**» и дисклеймер
   «заключение **не является диагнозом**» — находку НЕ гасят.

3. **Три статуса находки + human-in-the-loop**
   `trigger` / `uncertain` / `negated`. Спорное («нельзя исключить») не автоматизируется,
   а идёт в очередь «Требует уточнения» с кнопками «Подтвердить / Отклонить».

4. **Детерминированная маршрутизация и приоритеты**
   Матрица «находка → специалист → шаг → срок». Приоритеты `Экстренно / Срочно / Планово /
   Наблюдение` со SLA; очередь сортируется по срочности, просрочка подсвечивается.

5. **Объяснимость каждого срабатывания**
   Цитата из протокола с подсветкой, маркер сомнения, уверенность, версия правила — для каждого решения.

6. **Уведомление пациенту без диагноза**
   Текст собирается только из специалиста, нейтрален по формулировкам; при нескольких находках —
   **одно агрегированное** сообщение (защита от «переспама»).

7. **Сквозной маршрут и модельное время**
   Уведомление → запись → приём → тактика → госпитализация → операция → контроль.
   Шаги 24 ч / 72 ч / 7 / 14 / 30 дней отрабатывают за секунды (напоминания, обзвон, «не вовлечён»).

8. **Ничего не теряется**
   Протоколы без находок сохраняются в разделе **«Без патологий»** с заключением и полным текстом.
   Полный протокол доступен и в карточке врача (первоисточник).

9. **Версионирование и защита от изменений**
   `integrity.py` (версия правил + checksum), `snapshot.py`/`share.py` (снимки и архив проекта).

## 6. Демонстрация (60 секунд)

1. Открыть **http://127.0.0.1:8000**.
2. Нажать **«+ Загрузить протокол»**, перетащить `.docx` из `materials/protocols/...`.
3. Система: находит находку с **цитатой**, определяет **срочность и специалиста**, создаёт
   **маршрут**, готовит **уведомление пациенту без диагноза** (блок «Глазами пациента»).
4. Если формулировка спорная — находка уходит в **«Требует уточнения»**.
5. Кнопки **+24 ч / +72 ч / +7 дн** показывают сценарии, растянутые на дни.
6. Вкладка **Дашборд** — воронка «находка → приём → операция → контроль».

## 9. Ограничения и риски

- Свободный текст врачей разнообразен: правила требуют **сопровождения медэкспертом** и клинической валидации.
- Прототип демонстрирует распознавание и маршрутизацию; это **не медицинское изделие** без валидации и регистрации.
- Доступа к МИС/расписанию/ЛК нет — интеграция описана контрактом, уведомления имитируются.
- Экстренные находки — только **эскалация персоналу**, без самостоятельных назначений.
- Требуется защита от «переспама» (одно агрегированное уведомление) и минимум медданных в сообщениях.

## 10. План пилота и развитие

1. **Валидация правил** с медэкспертом на расширенной выборке; фиксация версии правил.
2. **Интеграция с МИС (1С)** по событийному контракту: событие «протокол закрыт», идемпотентность,
   обработка исправления/аннулирования без дублей.
3. **Развёртывание в контуре клиники**: локальная модель и OCR, без выхода данных наружу.
4. **Масштабирование** на новые специальности и типы исследований (правила как настройки).
5. **Замер эффекта**: конверсия в профильный приём, время до следующего действия, снижение ручного контроля.

## 11. Ключевые аргументы для оценки

- Полнота **100%** (ни одного пропуска) при точности **98.8%** на реальных протоколах.
- **Объяснимость**: каждое срабатывание — с цитатой, версией правила и уверенностью.
- **Безопасность**: без диагноза пациенту, без ПДн, локальный контур, human-in-the-loop для спорного.
- **Масштабируемость**: новый триггер/исследование — настройка, а не код.
- **Сквозной сценарий**: от находки до контрольного визита, с модельным временем и эскалациями.
- **Воспроизводимость**: версия правил видна в интерфейсе, метрики считаются скриптом.
